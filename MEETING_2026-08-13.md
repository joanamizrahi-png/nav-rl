# Meeting notes — 2026-08-13

## This week in four results

1. **The RGB problem is solved, and inference is now ONE pass.**
   The semantic losses were dragging RGB (measured: SSIM 0.25–0.6 vs the
   pretrained model off-path). Added an RGB-preservation loss (second forward
   with our additions switched off = the pretrained model, pin RGB to it) +
   min-SNR loss weighting (the VDM paper's point, made explicit). Result: the
   finetune's own RGB now matches the pretrained model's fidelity to real
   footage (13.7 vs 13.2 dB / 18.7 vs 19.2 dB). So RGB + semantics come from
   a single pass, aligned by construction — the two-pass workaround is
   retired (kept as a paper ablation; we also built latent anchoring, which
   proved alignment-by-force works before we made it unnecessary).
   → show: 05_semantics/v10_v11_verdicts/ONEPASS_*.mp4

2. **Best semantic accuracy so far, via the learned reader.**
   The CE loss at ALL timesteps (your suggestion) quietly trained a strong
   per-pixel reader; using it as the decoder instead of nearest-palette-color:
   **79.9% / 80.6%** held-out (v9 was 78.8 / 69.9), vegetation-vs-grass
   confusion largely resolved. Every ingredient was ablated individually:
   all-timestep CE +4.4, preservation at 0.3 (not 1.0) +2.4, min-SNR +6.1
   alone, bigger reader head +1.1. v11 (winners composed) trained overnight,
   grades landing today — targets ≥82 / ≥80.
   → show: v10_v11_verdicts/READER_*.mp4 and ABLATIONS_*.mp4

3. **Heading made visible (your rollout-video item) — and it caught a real bug.**
   Eval videos now draw the heading arrow + a goal compass. Building the
   "given a pose, is the image direction correct" probe uncovered a
   CONFIRMED yaw mirror: commanded turn-left renders as a visual turn-right,
   on both scenes tested (sweep videos make it unambiguous). Cause: the nav
   coordinate frame is left-handed, so rotation signs are mirrored between
   pose math and image. The sim is fully self-consistent, so every policy
   result stands — but the real robot would steer mirrored. Fix: make the
   nav frame right-handed at the calibration level (one place, fixes env +
   obs + overlays together), re-probe, and let the planned v14 policy
   retrain absorb it — zero extra training runs.
   → show: 06_diagnostics/yaw_sweep_*.mp4 ("turning left" label, view turns
     right), 04_rl_policy/rollouts_with_heading_overlay/

4. **Literature check on our fixes (deep-research sweep, cited report):**
   the 2024–26 co-generation papers (UDPDiff, IDC-Net, GeoVideo, SP4D,
   One4D) manage RGB via training recipes or hard isolation — none uses a
   preservation loss, none measures per-pixel drift vs the base model, and
   train-time anchoring has no prior art. Three candidate novelty claims.

## If asked — how to explain each piece (say-out-loud versions)

- **Where does the learned reader come from?** It was never built as a
  decoder — it's the small conv net that the pixel-space CE loss has needed
  since v8 (the loss compares class scores to ground truth, and something
  has to turn the decoded color map into class scores — that's the reader).
  It trains alongside the model and is saved in every checkpoint. We just
  started USING it at inference instead of snapping to the nearest palette
  color.
- **Why does the reader beat palette-snap now when it lost on v9?** Two
  things changed at once: the CE loss at all timesteps trained the reader on
  blurry half-denoised maps (much harder curriculum → much stronger reader),
  and the preservation loss made the model's color maps softer (softness is
  exactly what breaks nearest-color snapping). Fixed decoder broke, learned
  decoder adapted.
- **What is the preservation loss?** Our surgery kept the pretrained weights
  intact — the additions can be switched off. During training we run each
  input a second time with them off (that IS the pretrained model, no extra
  copy in memory) and penalize the distance between the two RGB predictions:
  "learn semantics however you like, your RGB output stays where the
  pretrained model's is."
- **What is min-SNR weighting?** Training picks a random noise level per
  step. Noise-target vs clean-target training are the same objective with
  different per-noise-level weights (the VDM paper), so we set the weights
  explicitly: cap them so no noise regime dominates; the informative middle
  gets the most say.
- **What was anchoring and why is it retired?** Inference-time trick: record
  the pretrained model's denoising trajectory, overwrite the semantic
  pass's RGB half with it at every step — semantics are then forced to
  describe the pretrained image. It worked (pixel-exact), but once the
  preservation loss made our own RGB just as good, the second pass stopped
  buying anything. Kept as the experiment that proved one-pass is safe.
- **Why did accuracy numbers dip mid-week then beat everything?** v10's
  snap-decoded numbers dipped (70.0/54.8) because snap can't read soft maps;
  the model's understanding was fine — same checkpoint with the reader:
  79.9/80.6. Decode problem, not model problem.
- **Is the yaw bug in our results?** No — the sim is self-consistent
  (mirrored world, mirrored controls, they cancel). It only matters for
  transferring to the real robot, which is why we're fixing it now, before
  deployment.
